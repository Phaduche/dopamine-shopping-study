# ORDERTRACE · VISTA-01 시각 순서 과제

**연구 질문:** 저속 촬영 프레임을 **그대로 반복**한 영상과 컴퓨터가 **중간 프레임을 생성(보간)**한 영상에서,
사람이 두 사건(빨간 물체·파란 물체가 흰 선을 통과)의 실제 순서를 다르게 판단하는가?

## 실행

```bash
python3 ordertrace/make_stimuli.py   # 자극 생성 (약 10초) → ordertrace/stimuli/
python3 server.py                    # 또는 --lan
```

- 참가자 페이지: http://localhost:8000/ordertrace/
- 연구자 콘솔(응답 수·조건별 오순서 단정률·CSV): http://localhost:8000/admin.html

## 자극 설계 (`make_stimuli.py`)

| 항목 | 값 |
| --- | --- |
| 원본 | 320×240, 120fps, 1.0초 합성 영상. 빨간 원(x=100)·파란 원(x=220)이 아래로 움직여 y=150 흰 선을 통과 |
| 정답 | 해석적 궤적에서 통과 시각을 계산. SOA>0이면 빨강이 먼저 |
| 관측 fps | 5 / 10 / 15 (위상은 클립마다 무작위) |
| 재구성 | `repeat`: 관측 프레임 반복(hold) · `interp`: Farneback 양방향 광학흐름 + 가중 혼합(고정 파라미터) |
| 출력 | 두 방식 모두 60fps, 60프레임, 같은 해상도 (스프라이트 시트 JPG) |
| SOA | ±33ms, ±83ms (본시행) · 167ms (연습) |
| 운동 | 가속(accel) / 감속(decel) — 등속이면 선형 보간이 정확해서 순서가 바뀔 여지가 없음 |
| 본시행 | 4 SOA × 3 fps × 2 방식 = 24회, 참가자마다 무작위 순서, 12회 뒤 휴식 |

설계를 바꾸려면 파일 위쪽의 `SOAS_MS`, `FPS_LEVELS`, `METHODS`, `PROFILES`를 고치고 다시 실행합니다.
`--seed`를 바꾸면 위상·통과 시각의 무작위 값이 달라집니다.

## 과제 (`index.html`, `task.js`)

참가자 코드·동의 → 안내 → 연습 1회(피드백, 틀리면 재시도) → 본시행 24회 → 완료(확인 코드, CSV 저장, 상세 목적).
영상은 캔버스에서 60fps로 **1회만** 재생되고(3초 카운트다운), 응답은 4지선다(A/B/S/U 단축키) + 확신도 0~100.
재생 중 건너뛴 프레임 수와 재생 길이를 기록해 `anomaly`(건너뜀 >3 또는 길이 오차 >150ms)로 표시합니다.

## 데이터

- `ot_sessions`: 세션 id, 참가자 코드, 시작·완료 시각, 시행 순서, 확인 코드
- `ot_trials`: 시행별 조건(방식·fps·SOA·운동·정답), 응답, 확신도, 반응시간, 재생 이상
- CSV(`/api/export/ordertrace.csv`)의 `wrong_definite` = 실제 순서와 다른 특정 순서(red/blue)를 단정한 시행 → **단일 1차 결과**는 이 비율의 방식 간 차이
- 서버가 없어도 응답은 기기(localStorage)에 남고 완료 화면에서 CSV로 내려받을 수 있습니다.

## 주의

- 합성 자극은 파일럿·기술 점검용입니다. 본실험에는 120fps 실촬영 영상으로 자극을 교체하는 것을 권장합니다(생성기의 `source_frames`만 바꾸면 됩니다).
- 사람 대상 자료 수집은 IRB 승인 뒤에만 합니다.
